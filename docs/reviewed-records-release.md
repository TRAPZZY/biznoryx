# Reviewed records, Money Trail and monthly review

This is the second release increment after PR #28. Do not equate a green build with production feature activation. No production SQL has been applied by this implementation work.

## Customer workflows

- **Data & uploads:** review CSV or values-only XLSX, select a sheet, confirm source role, currency, date convention and column mapping. Reuse the approved profile next month; changed columns require new approval. Identical source/profile/period retries return the existing run. Replacements explicitly identify the prior upload in the same series/month.
- The original artifact and the normalized worker CSV have separate checksums and object identities. Registration binds them in one database transaction. Original-file download retrieves and verifies the original bytes, including XLSX and UTF-8 BOMs. The existing CSV intake and manual-entry path remain available.
- An approved date convention normalizes the worker date column to ISO text without changing original bytes or source-record numbering. The manifest records that transformation; financial review reads the normalized convention. Currency changes or changing an established financial source role require a separate series. Financial mappings must match the confirmed business reporting currency; no currency conversion is implied. Row errors can be downloaded as CSV with formula-injection protection.
- **Map records** attaches a reviewed profile to an existing accepted CSV/manual snapshot without re-uploading it or changing its original analytics. A recorded profile is frozen for that source.
- **Sales & receipts:** preview financial rows from the verified stored source, confirm them, review record meaning and approve allocations. Initial financial scope is NGN. Dates use the approved convention; decimals remain strings. Missing payment status stays unknown. References must be confirmed before exact-reference suggestions; suggestions never allocate automatically.
- Partial allocations, credits, refunds and append-only reversals conserve amounts under ordered record locks and database guards. A source correction requires an explicit prior source and reason, and its active allocations must be reversed first. The old source remains evidence; its superseded records are excluded from current totals. Correction history links both sources.
- **Monthly review:** confirm the month's required source series, prepare a server-calculated packet, inspect limitations and approve as an owner/admin. Missing, failed, pending or partial required sources block approval. The packet pins its metric definition, verified source points, source checklist and financial snapshot. Newer approval can explicitly supersede an older packet without changing the older values. SHA-256 is an integrity check, not an external audit or digital signature.
- Existing Updates delivers mapping changes, ready monthly drafts and financial review events through the durable notification path. Business defaults and recipient preferences apply. No email/SMS/device-push provider was added.

## Explicit first-release limits

- Reviewed CSV/mapping: 4 MiB; XLSX: 2 MiB compressed, 4 MiB total expansion, 256 ZIP members, 10,000 data rows, 200 columns and 50,000 cells. The 15-second parser process has a 24 MiB old-generation heap limit and a 96 MiB RSS watchdog. One XLSX parser runs per API process; competing requests receive a retryable error. These ceilings are safeguards, not performance guarantees. Validate under the actual 256 MiB production container before activation.
- The existing direct CSV upload retains its 25 MiB ceiling. It does not approve an import profile. Text must be valid UTF-8. XLSX formulas/cached formulas, date-valued cells, external links, macros, encryption, merged cells and legacy XLS are rejected with a safe CSV/values-only alternative. ISO **text** dates are supported. This release does not enable production PDF, arbitrary JSON, TSV or OCR ingestion.
- Financial source review accepts up to 1,000 records per source. Financial detail lists are capped at 500; aggregate totals cover the full selected period. Snapshot approval refuses capped financial evidence. No conversion, bank connection, guessed fees, automatic debt collection, recognition of profit or automatic matching is introduced.
- Live financial balances include later approved receipts for the selected sales; receipt totals keep their actual receipt dates. Monthly snapshots preserve their preparation-time basis and explicitly do not claim complete bank/cash reconciliation. Source coverage is owner-supplied information, not proof that omitted business activity does not exist.
- Previously truncated report cubes require authorized reprocessing to recover dates/categories. PR #28 prevents new truncation; it does not invent or silently backfill historical evidence.

## Retention and evidence withdrawal

Immutability is an application integrity rule, not permission to retain personal data forever. The authorized deletion/retention operation must include import manifests/profiles, original/normalized object keys, financial imports/records/states/classification history/allocations/reversals/source supersessions and monthly packets/approvals/source requirements. Financial retention exceptions require documented justification. No production retention commitment or deletion automation is claimed by this release.

Quarantining/withdrawing a source causes repository evidence checks to report it unavailable. Packet retrieval also checks object presence/size; downloads verify full bytes and checksum. Archived numbers cannot imply the underlying evidence still exists. A legally required packet purge must use a separately authorized privileged maintenance path; routine source correction cannot erase history.
